Research interests

The problems I keep coming back to.

  • Embedded systems

    Firmware, real-time control and model-based design on ARM Cortex-M, STM32 and ESP32.

  • Internet of Things

    Sensor networks, MQTT telemetry and dashboards that make a fleet of devices legible.

  • Edge computing

    Pushing the decision to the device — latency, privacy and bandwidth budgets that hold.

  • Embedded AI

    Small models on small silicon: quantised inference where there is no cloud to call.

  • Digital twins

    Simulating a plant well enough that the model, not the hardware, catches the bug first.

  • Computer networks

    Protocol behaviour under load, and the gap between the RFC and the wire.

  • Cybersecurity

    Cryptographic primitives in hardware, key management, and building things that fail closed.

  • Working on something in this space?

    I would like to hear about it.

Projects

Selected work — all of it open on GitHub.

Hardware · FPGA

FPGA digit convolution accelerator↗

A hardware convolution accelerator that detects the digits 8 and 9 in a 64×64 grayscale image, driven over AXI4-Lite from a Zynq PS and deployed to a remote FPGA board.

  • Verilog
  • AXI4-Lite
  • Zynq
  • RemoteFPGA
Embedded AI · IoT

Edge-AI motion classification↗

An AIoT pipeline that classifies motion from simulated MPU6050 sensor data: inference runs at the edge through Edge Impulse WebAssembly, results travel over MQTT, and ThingsBoard handles live monitoring and alerts.

  • Edge Impulse
  • WebAssembly
  • MQTT
  • ThingsBoard
IoT

Smart home over KNX↗

A smart-home system joining KNX devices to ThingsBoard, with MCP and a locally hosted Ollama model giving it Persian natural-language control.

  • KNX
  • ThingsBoard
  • MCP
  • Ollama
  • TypeScript
Real-time · Model-based

Real-time heating controller↗

A multi-room heating controller modelled end-to-end under the V-model: thermostat logic, a safety checker and room thermal dynamics in Simulink and Stateflow, validated with Simulink Test and Embedded Coder.

  • MATLAB
  • Simulink
  • Stateflow
  • C
Crypto hardware

Triple DES, three architectures↗

Two-key 3DES in Verilog, built three ways — single-cycle, multi-cycle and pipelined — with ECB, CBC and OFB modes, so the area/throughput trade-off is measurable rather than argued.

  • Verilog
  • 3DES
  • Pipelining
Crypto hardware

Montgomery modular exponentiation↗

Modular exponentiation in hardware, assembled from Montgomery multiplication, Karatsuba multiplication, non-restoring division and the extended Euclidean algorithm.

  • Verilog
  • Montgomery
  • Karatsuba
Crypto hardware

TEA on a remote FPGA↗

The Tiny Encryption Algorithm implemented on remote Mitra Z10/Z20 boards, wired to the processing system through AXI4-Lite and built with Vivado and the Xilinx SDK.

  • Verilog
  • Zynq
  • Vivado
  • AXI4-Lite
Processor design

Pipelined MIPS processor↗

A MIPS processor in Verilog, down to the ALU and memory subsystem — the whole datapath rather than a block diagram of one.

  • Verilog
  • MIPS
  • Datapath
Operating systems

Operating system simulator↗

An educational OS simulation with a CPU, MMU, threads and a file layer, used to study page-replacement, virtual memory, synchronisation and scheduling under measurable fault behaviour.

  • Python
  • Virtual memory
  • Scheduling
Applied cryptography

Secure client–server system↗

A two-phase cryptography project: symmetric encryption, RSA and DSA, a small PKI with certificate management, and a client–server channel built on top of it.

  • Python
  • RSA
  • DSA
  • PKI
Game AI

Hand of the King agent↗

A minimax agent whose heuristic weights were tuned by a genetic algorithm. Third place in the course AI competition.

  • Python
  • Minimax
  • Genetic algorithm
Digital design

Transistor-level logic in Verilog↗

A logic function built from transistor primitives rather than gates — the level where the abstraction stops being free.
